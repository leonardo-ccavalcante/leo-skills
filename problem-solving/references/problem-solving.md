# Problem Solving — Referencia Completa

## ¿Qué es Problem Solving?

El proceso de encontrar respuestas a cuestiones difíciles y complicadas personales y profesionales.

**Tu habilidad de resolver problemas y tomar buenas decisiones es central para tu efectividad en el trabajo.** Sin embargo, la mayoría nunca ha sido enseñada formalmente cómo resolver problemas.

### Áreas de Reflexión para Evaluar Tu Enfoque Actual

- **Actions**: ¿Qué pasos tomas?
- **Stakeholders**: ¿A quién involucras?
- **Approach**: ¿Cómo te ajustas para diferentes tipos de problemas?
- **Toolkit**: ¿Qué recursos usas?
- **Strengths**: ¿Qué haces bien?
- **Opportunities**: ¿Cómo podrías mejorar?

## Los 3 Horizontes de Tiempo

### 1. Problem Solving en el Momento
- Muy poco tiempo formal para estructurar
- Preguntas clave: ¿Has definido el problema? ¿Están alineados los stakeholders? ¿Está delimitado el espacio de soluciones?
- Requiere pensamiento rápido, claro y sin papeles

### 2. Problem Solving en 1-2 Semanas
- Más tiempo para análisis
- Probablemente más cosas que revisar de las que tienes tiempo
- **Prioritiza** los issues y los análisis a conducir

### 3. Problem Solving en Proyecto a Largo Plazo
- Más tiempo pero también más complejidad y más valor en juego
- Considera: dependencias, stakeholders a alinear, decisiones tempranas con impacto en cascada
- Las decisiones iniciales tienen "knock-on effects" que afectan todo el proyecto

## Caracterizando Problemas

### Pensamiento Convergente vs. Divergente

| | Convergent Thinking | Divergent Thinking |
|---|---|---|
| **Objetivo** | Encontrar la mejor respuesta única | Explorar nuevas posibilidades |
| **Proceso** | Eliminación de opciones, establecer hipótesis | Crear rango amplio de opciones |
| **Útil cuando** | Hay una solución óptima clara | Se requiere innovación |

**El balance es crítico:**
- Error 1: Usar pensamiento analítico/convergente a un problema que requiere pensamiento creativo
- Error 2: Pasar demasiado tiempo en divergencia sin converger en una solución

## Los 5 Enfoques de Problem Solving

Los cinco enfoques comparten 5 características comunes:
1. **Focused problem statement** — pregunta de problema clara y específica
2. **Impact-oriented** — orientado al impacto real
3. **Stakeholder perspective** — considera a las personas afectadas
4. **Fact-based** — basado en hechos y datos
5. **Focus on synthesis** — busca el "y qué", no solo los hechos

### Los 5 Enfoques

**1. Hypothesis-Led Approach**
- Útil cuando tienes suficiente información para hacer una hipótesis temprana
- Trabajo top-down: define el problema y la hipótesis primero, luego valida/invalida
- Define: ¿qué hipótesis estás tratando de probar o refutar?

**2. Domain IP-Led Approach**
- Basado en expertise de dominio específico
- Aplica conocimiento profundo del sector/área al problema

**3. Advanced Analytics Approach**
- Cuando tienes grandes cantidades de datos involucrados
- Data-driven insights, análisis cuantitativos
- Útil para encontrar patrones en datos complejos

**4. Design Thinking Approach**
- Centrado en el usuario/humano
- Iterativo: empatiza → define → idea → prototipa → testea
- Útil para problemas de experiencia, innovación de producto/servicio

**5. Engineering Approach**
- Técnico y sistemático
- Útil para problemas con soluciones técnicas claras
- Proceso disciplinado de construcción y verificación

## Problem Structuring: El Poder de la Estructura

### Por Qué Estructurar

Sin un plan claro, el análisis abre más preguntas de las que resuelve. En el mundo real, casi siempre carecemos del tiempo para abordar cada aspecto. **Cómo estructuras y priorizas es la clave para usar tu tiempo limitado en el área correcta.**

### Issue Trees (Árboles de Cuestión)

Un issue tree comienza con el problema definido en la raíz y lo descompone en preguntas cada vez más granulares.

```
PROBLEMA DEFINIDO
       │
       ├─→ Pregunta Principal 1
       │   ├─→ Sub-pregunta 1A
       │   ├─→ Sub-pregunta 1B
       │   └─→ Sub-pregunta 1C
       │
       ├─→ Pregunta Principal 2
       │   ├─→ Sub-pregunta 2A
       │   └─→ Sub-pregunta 2B
       │
       └─→ Pregunta Principal 3
           ├─→ Sub-pregunta 3A
           └─→ Sub-pregunta 3B
```

**Cómo construir un issue tree:**
1. Empieza con el problema como raíz
2. Identifica 3-5 preguntas o áreas principales
3. Para cada una, descompón en sub-componentes
4. Continúa hasta alcanzar componentes analizables
5. Revisa MECE en cada nivel
6. Itera conforme obtienes nueva información

### El Principio MECE

**Mutually Exclusive, Collectively Exhaustive**
- **Mutually Exclusive**: Las categorías NO se superponen — no hay traslape
- **Collectively Exhaustive**: Las categorías juntas cubren TODAS las posibilidades

Objetivo: Categorías que no se repiten y que entre todas cubren el espacio completo del problema.

## Priorización

La priorización responde: ¿Qué análisis vas a hacer dado el tiempo y recursos disponibles?

**Factores a considerar:**
1. **Impact** — ¿Qué tendrá el mayor efecto?
2. **Time** — ¿Cuánto tiempo tienes?
3. **Resources** — ¿Qué recursos están disponibles?
4. **Dependencies** — ¿Qué debe hacerse primero?
5. **Stakeholder needs** — ¿Qué importa a los stakeholders clave?

**Enfoque práctico:**
- Mapea issues por impacto vs. esfuerzo
- Identifica quick wins
- Enfócate en áreas de alto impacto
- Balancea corto y largo plazo

## Caso de Estudio: CarneCarne

**Situación:** Contaminación de E. coli en muestras de carne congelada en el centro de distribución noroeste.

**Pregunta del Problema:** "¿Cuál es la fuente de la contaminación de E. coli en las muestras de carne congelada en el centro de distribución noroeste?"

**Cadena de Suministro:**
```
5 Granjas Familiares
    ↓
Instalación de Empaque
    ↓
Centro de Distribución NW  ← [punto de detección]
    ↓
3 Tiendas CarneCarne
    ↓
Consumidores
```

**Aplicación del Issue Tree:**
- El problema se estructura como MECE para asegurar que todas las posibilidades estén consideradas
- Las ramas del issue tree mapean los puntos de la cadena de suministro donde puede originarse la contaminación
- La priorización determina dónde enfocar la investigación primero

## Key Takeaways — Problem Solving

- Los profesionales resuelven problemas diariamente; la efectividad en problem solving es central a tu trabajo
- Diferentes horizontes de tiempo requieren diferentes enfoques
- Balance entre pensamiento analítico y conceptual, convergente y divergente
- Los 5 enfoques comparten características comunes: problema definido, orientado al impacto, perspectiva de stakeholder, basado en hechos, enfocado en síntesis
- La estructuración con issue trees y MECE ayuda a organizar el análisis
- La priorización es crítica dado el tiempo y recursos limitados del mundo real
- La síntesis (no solo el resumen) es el objetivo final del análisis
