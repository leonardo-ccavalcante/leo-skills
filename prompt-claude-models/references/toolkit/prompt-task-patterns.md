**Conflitos brandos (7)**, pela linha da §2 que os resolve:

- *Prefill / deixa de completion* — `references/classification.md:59` — a deixa (`A:`, `Category:`, `Observation:`) só é segura dentro do turno `user`; nunca como última mensagem `assistant` (400 em [PREFILL]); formato por Structured Outputs ou enum. **Reforços (18)**

- `SKILL.md:53` · Classificação com saída restrita a um rótulo — Em Claude, garantir o rótulo com structured outputs (enum com os rótulos + "other"/"uncertain") ou uma ferramenta com campo enum, em vez de confiar só na instrução. No Opus 5.5 e no Fable 5.1, manter tool_choice "auto" (forçar "any"/"tool" dá 400) e usar strict tool use. (claude-prompting-best-practices, "Migrating away from prefilled responses"); (whats-new-opus-5-5, "Forced tool use is not supported"); (whats-new-fable-5-1, "Forced tool use is not supported")
- `SKILL.md:68` · Extração para JSON — Em Claude, usar Structured Outputs com o schema dos campos (tipos nulos permitidos) em vez de só "Output JSON"; não usar prefill "{" para forçar JSON. (claude-prompting-best-practices, "Migrating away from prefilled responses")
- `SKILL.md:75` · Regra explícita de null por campo — Sonnet 5 e Opus 4.8 seguem instruções literalmente e não generalizam de um item para outro: manter "Null if not mentioned" em cada campo (como no esqueleto) e dizer explicitamente quando uma regra vale para todos os campos. (prompting-claude-sonnet-5, "More literal instruction following")
- `SKILL.md:90` · Tamanho do resumo fixado no prompt — No Opus 5 as respostas e os documentos escritos saem mais longos por padrão e o effort não encurta a resposta visível; fixar N bullets/frases no prompt é a alavanca certa. (prompting-claude-opus-5, "Response length and verbosity")
- `SKILL.md:93` · Fidelidade à fonte em resumos — No Fable 5.1, resumos tendem a reproduzir trechos da fonte sem marcá-los como citação; acrescentar ao system prompt um exemplo completo de resposta correta (pedido, resposta e uma frase dizendo por que está correta), com paráfrase e no máximo um trecho curto entre aspas. (prompting-claude-fable-5-1, "Quoting retrieved sources")
- `SKILL.md:111` · QA sem contexto (closed-book) e busca — Se o alvo Claude tiver ferramenta de busca, no Fable 5.1 em effort low ele tende a responder de memória: subir o effort nesses turnos ou acrescentar a instrução oficial de buscar nomes pouco conhecidos ou de áreas que mudam rápido. (prompting-claude-fable-5-1, "Search triggering at low effort")
- `SKILL.md:118` · Citações em RAG — Para Claude, em documentos longos, pedir primeiro as citações relevantes em <quotes> e só depois a resposta baseada nelas; combina com o [ID] por fato. (claude-prompting-best-practices, "Long context prompting")
- `SKILL.md:126` · Pergunta no fim do prompt — A pergunta no final já segue a regra de contexto longo; mover também as instruções para depois do <context> (ver conflito na linha 116). (claude-prompting-best-practices, "Long context prompting")
- `SKILL.md:139` · Implementação mínima — Em effort alto, o Fable 5 tende a arrumar e refatorar além do pedido (página citada); o Opus 4.5/4.6 tende a overengineering segundo claude-prompting-best-practices ("Overeagerness"). "smallest correct implementation" já aponta nessa direção e pode ser reforçado com o bloco oficial anti-overengineering. (prompting-claude-fable-5, "Consider all effort levels")
- `SKILL.md:139` · Escolha de modelo para geração de código — Para geração de código do dia a dia, começar pelo Sonnet 5; Opus 5.5 para agentes de código de várias horas e refatorações grandes; Fable 5.1 só se Opus 5.5 em xhigh/max ainda falhar nos evals. (choosing-a-model, "Model selection matrix")
- `SKILL.md:146` · Ambiguidade na especificação — No Fable 5.1 o padrão documentado é implementar a leitura mais bem apoiada pelo texto e pelo código e declarar a suposição no resumo, sem construir para as outras leituras; ajustar "list the ambiguities at the top" para não conflitar com "Return the code only" (linha 150), pois Sonnet 5 e Opus 4.8 seguem instruções literalmente. (prompting-claude-fable-5-1, "Keep changes and tests to what the task asks for")
- `SKILL.md:155` · APIs inventadas — Em Claude agêntico, acrescentar o bloco <investigate_before_answering>: ler arquivos e dependências antes de afirmar algo sobre o código. (claude-prompting-best-practices, "Minimizing hallucinations in agentic coding")
- `SKILL.md:157` · Modificar código existente — No Fable 5.1 em modo agêntico, pedir edições cirúrgicas em vez de reescrever o arquivo inteiro (o formato diff cumpre esse papel quando não há ferramenta de edição). (prompting-claude-fable-5-1, "Prefer targeted edits over whole-file rewrites")
- `SKILL.md:163` · Modelo para matemática — Para aplicações matemáticas/científicas, começar pelo Opus 5.5 (capability-first) e subir effort; migrar para Fable 5.1 só se xhigh/max ainda ficar aquém. (choosing-a-model, "Option 2: Start capability-first")
- `SKILL.md:184` · Variedade em escrita criativa sem temperatura — Para Claude a variedade vem das restrições do prompt e de propor direções, não de temperature/top_p/top_k: valores não padrão dão 400 no Sonnet 5 (e no Opus 4.7 e Fable 5.1, segundo os guias de migração). (prompting-claude-sonnet-5, "Tone and writing style")
- `SKILL.md:216` · Prompts de code review — Ao escrever o padrão de review para Claude, não filtrar por severidade ("only high-severity", "be conservative", "don't nitpick"): Opus 4.8, Opus 5 e Sonnet 5 seguem o filtro ao pé da letra e o recall cai; pedir cobertura total com confiança e severidade por achado e filtrar em outra etapa. (prompting-claude-sonnet-5, "Code review harnesses")
- `references/classification.md:78` · Escalar casos incertos para outro modelo — Padrão executor→advisor: classificar em modelo barato (Haiku 4.5 ou effort low) e escalar só os "uncertain" para Opus 5.5/Fable 5.1. (choosing-a-model, "Combine models")
- `references/classification.md:106` · Classificação em caminho quente — Antes de fine-tuning/destilação, testar Claude Haiku 4.5 (menor latência e preço) ou effort low no modelo atual; o ajuste de effort é a alavanca documentada de custo/latência. (choosing-a-model, "Model selection matrix")
