# Sobreposição: set `prompt-*` × modelos Claude atuais

Este arquivo é a camada Claude por cima das skills genéricas de técnica (`prompt-foundations`, `prompt-reasoning`, `prompt-output-control`, `prompt-orchestration`, `prompt-role-and-context`, `prompt-reliability`, `prompt-security`, `prompt-task-patterns` e o roteador `prompt-engineering-router`). Elas ensinam a técnica; este arquivo diz o que muda quando o modelo-alvo é Claude: o que continua valendo, o que muda de forma, o que troca de mecanismo e o que a API rejeita. É lido no passo 6 da espinha do `SKILL.md`, sempre que uma técnica do set entra no prompt.

**Como ler.** No passo 6, leia só a linha da técnica na tabela da §2 (`grep -n "^| <Técnica>" references/sobreposicao-toolkit.md`), o bloco da §2.1 que essa linha citar pelo id e, no Adaptar, o sintoma da §2.2; da §1, só a legenda de grupos quando a linha usa um rótulo como [LIT] ou [TODOS] (o resto da §1 explica como as camadas se compõem e não é preciso para montar). A §3 e os arquivos de `references/toolkit/` (um por `prompt-*`, mais `references/toolkit/prompt-engineering-router.md` para o roteador) são manutenção do toolkit: dizem que trecho de cada `prompt-*` e do roteador contradiz a camada Claude e o que mudar lá. Não servem para montar prompt.

Fontes: as páginas oficiais em `fontes.json` (citadas como `(page_id, "seção")`) e o levantamento verificado, linha a linha, dos arquivos do set (citado como `skill/arquivo.md:linha`, caminho relativo à raiz do repositório de skills). Linhas conferidas contra os arquivos em 27/09/2026. Se o arquivo do toolkit mudou desde então, localize o trecho pela citação, não pelo número.

## 1. Como as duas camadas se compõem

**Das `prompt-*` para cá.** Quando o alvo é Claude, a saída de qualquer `prompt-*` termina aqui antes de ser entregue: a técnica escolhida lá passa pela linha correspondente da tabela da §2, e os conflitos listados no arquivo da skill em `references/toolkit/<skill>.md` (índice na §3) apontam exatamente que trecho do toolkit não vale para qual modelo. Cada `SKILL.md` do set já traz uma linha-ponteiro `Claude target?` que manda aplicar `prompt-claude-models` (local e divergências no arquivo da skill em `references/toolkit/`); o roteador recebe os pontos de integração de `references/toolkit/prompt-engineering-router.md`.

**Daqui para as `prompt-*`.** Quando o diagnóstico (passo 4) ou a montagem (passo 6) pede uma técnica — few-shot, cadeia, schema, defesa de injeção, eval, receita de tarefa —, chame a `prompt-*` dona (pelo roteador, se houver dúvida de qual) para desenhar a técnica e aplique a linha da tabela por cima. Esta skill não reensina técnica genérica; ela só corrige, ajusta ou reforça.

**Precedência.** Vale a hierarquia do `SKILL.md`: restrições duras da API > guia oficial do modelo > `MEMORY.md` > política local > defaults. Esta sobreposição é uma leitura das páginas oficiais: onde ela e o `modelos/<modelo>.md` divergirem, vale o guia do modelo; o texto genérico da `prompt-*` fica abaixo de ambos. Para alvo que não é Claude, a `prompt-*` vale sozinha e esta camada não se aplica.

**Vereditos**

| Veredito | Significa |
|---|---|
| **manter** | a técnica vale como o toolkit descreve; a sobreposição só reforça ou acrescenta detalhe Claude |
| **ajustar** | vale, mas muda de forma: quantidade, posição, tag, formulação ou parâmetro |
| **substituir** | o objetivo continua, o mecanismo é outro (outro recurso da API ou outra técnica) |
| **obsoleta** | o mecanismo quebra (400) ou deixou de ter função nos modelos indicados |

## 3. Por skill `prompt-*`: conflitos, reforços e integração com o roteador


Formato: cada **conflito duro** traz local, trecho, modelos afetados, regra (com a fonte) e correção. Os **conflitos brandos** aparecem agrupados pela linha da tabela da §2 que os resolve. **Reforços** são pontos em que o toolkit está certo e a camada Claude acrescenta um detalhe. **Menções defasadas** não são regra de modelo, mas enganam quem lê com alvo Claude. O **ponteiro** é a linha `Claude target?` que cada `SKILL.md` do set já traz; o arquivo da skill em `references/toolkit/` dá o local e só aponta onde o texto instalado diverge desta sobreposição. Os números entre parênteses contam os itens de cada lista. Dentro de cada arquivo de `references/toolkit/`, os caminhos são relativos à pasta da skill (`SKILL.md:83` = `prompt-foundations/SKILL.md:83` em `references/toolkit/prompt-foundations.md`); arquivos fora dela aparecem com o caminho completo.

Esta seção e os arquivos de `references/toolkit/` são manutenção do toolkit. Para montar prompt, a §2 basta.
